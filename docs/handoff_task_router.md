## 4. What is built

### Router (`src/hipstraw_mm/market/router.py`, `config/routing.yaml` router.v1)
- `decide_route` is an ordered rule list, no model call:
  R1 task not in table → frontier · R2 a listed rule answers this input, or class rules → rules ·
  R3 complex → frontier · R4 open-weight route off → frontier · R5 no endpoint configured → frontier ·
  R6 input over `maxInputChars` (100,000) → frontier · R7 3 open-weight **call failures** in a row in the
  stage → frontier · R8 simple → open-weight.
- `TaskRouter.call(step, schema, messages, task, match_key, validate=, rule=, log_run_id=)`:
  open-weight answer kept only if every **blocking** check passes; otherwise (or on schema error, HTTP
  error, timeout, missing replay recording) the same messages go **once** to frontier under today's match
  key. Frontier results are validated too but only recorded. Non-blocking checks are warnings.
- Lineage: business step `outputs.routing` {routerVersion, task, class, ruleId, why, route, servedBy,
  escalated, escalationReason, attempts, validation{open_weight, frontier}}; every attempt is a
  `call_model` worker step (inputs carry route and model; schema-failed responses are stored too).
  Deliberations store `deliberatedBy`.
- Open-weight tier: any OpenAI-compatible endpoint via `OPEN_WEIGHT_BASE_URL`, `OPEN_WEIGHT_MODEL`,
  `OPEN_WEIGHT_API_KEY`; SDK retries off, 60 s timeout, one schema attempt. Replay keys
  `ow:<model>:<key>`; frontier keys unchanged.
- Ships dark: `openWeight.enabled: false`. With it off every call goes to frontier as before; the only
  behaviour difference is the buyers rule below (skips calls whose result is already known).

### Routing table today
| Task | Class | Validators (rules only) |
|---|---|---|
| vichara.v1 | simple | echo_key, grounding, abstention |
| link_verification.v1 | simple | coverage (each link once), rationale (≥3 words) |
| buyer_roles.v2 | simple + rule `no_passing_evidence` | path_echo, evidence_ids, one_company |
| query_plan.v2 (child) | simple | queries; metros (warning only) |
| listing_extraction.v2 (child) | simple | link_ids, excerpts (≥ half quoted from the page) |
| homepage_identity.v2 (child) | simple | consistency, homepage_excerpt |
| vichara_coverage, vichara_propose, graph_level, beam_scoring, path_assessment, economic_assessment, company_evidence, review_judgement | complex → frontier | stage's own checks |
| vichara_repair.v1 | not wired | rules candidate |
All have the schema ("Right form") check. Rubric: `config/validation.yaml` (validation.v3) with plain
questions, method, pass condition, on-fail action, tiers, blocking; tests keep it in step with the code.

### Validation details
- Grounding diagnosis (`market/vichara.py: explain_grounding_miss`): for a failed quote, the closest
  passage, words matched, first difference (replaced / missing / extra word, or characters) and unusual
  characters, with verdict near_miss / partial / not_found. On the Kozmo PDF most failures are near
  misses caused by PDF characters (U+02BC apostrophe, U+E088 private-use dash, trailing punctuation).
- Abstention: an open-weight "no information" while documents are attached escalates (frontier
  recovered real answers in 5 of 8 cases on the first live run).

### Child runs (`src/hipstraw_mm/market/child_routing.py`)
- Inside a market run, `stage_companies` sets `ctx.router`; each child model call is its own traced
  step (`plan_queries`, `extract_listing`, `read_homepage`, `extract_evidence`, `judge_company`) with worker
  steps beneath. Outside a market run (feature 002 alone) the call is the plain one. Budgets use
  `ctx.model_calls()` (both tiers). Claimed in `config/agents.yaml`.

### Simulation and viewer
- `hipstraw-mm market --memory simulate --program invoice_alpha_genesis --objective-pdf "<pdf>"
  [--through STAGE] [--run-id ID] [--serve]` runs the pipeline to STAGE with the open-weight route on for
  that run only (`routing_override`), marks the run `simulation`, prints a walk-through, writes
  `reports/<run>_routing.json`, and with `--serve` prints `routing: http://127.0.0.1:8765/#/run/<id>/routing`.
- Viewer **Routing** tab (`viewer/static/index.html`, API `/api/runs/<id>/routing` from
  `market/routing_report.py`): animated routing diagram (rule lamps R1–R8, validation lamps per task),
  task panel with validation log and escalation reason, counters (kept / escalated / straight to frontier
  / rules / not routed), cost against an all-frontier estimate, task table with stage filter and links to
  Activity steps, validation rubric per task.

## 6. Decisions and why
- Slice order followed an adversarial design review: vichara first (all diagram branches, traced calls),
  then links/buyers, then child runs.
- R7 counts only call failures; weak answers escalate one by one (a live run showed the first version
  wrongly sent 8 dimensions straight to frontier).
- `maxInputChars` raised 60K → 100K (links prompts are about 65K; 100K chars ≈ 25K tokens fits the 32K
  minimum context from the model research). Awaiting Ashish's OK.
- Frontier is the last tier: its validation is logged, never rejects; each stage keeps its own handling.
- Behaviour changes are not made without sign-off (Constitution X).
